2. THE UNIFIED ARCHITECTURAL PRINCIPLE ("Three Interfaces, One Source of Truth")
====================================================================================================
A fundamental rule governs this entire codebase:
THERE ARE THREE INTERFACES, BUT NEVER THREE SEPARATE SYSTEMS.

                                 +-----------------------+
                                 |    GLOW & GLAMOUR     |
                                 |   SINGLE FIRESTORE    |
                                 +-----------+-----------+
                                             |
                   +-------------------------+-------------------------+
                   |                         |                         |
        +----------v----------+   +----------v----------+   +----------v----------+
        |   CUSTOMER PORTAL   |   |      OWNER CRM      |   |      STAFF CRM      |
        |  (Public + Private) |   |  (Executive Suite)  |   |    (Operations)     |
        +----------+----------+   +----------+----------+   +----------+----------+
                   |                         |                         |
                   +-------------------------+-------------------------+
                                             |
                            SINGLE APPOINTMENT RECORD LIFECYCLE
               Booked -> Confirmed -> In Progress -> Completed / No Show / Cancelled

When Customer Rahul books a Haircut at 5:00 PM:
1. Exactly ONE record is created in the `appointments` collection.
2. Rahul sees it immediately in his Customer Dashboard and gets a downloadable QR Ticket.
3. The Owner sees Rahul on the Owner Appointments schedule and Dashboard metrics.
4. The assigned Stylist sees Rahul on their personal Staff daily schedule.
5. If the Owner or Staff marks the appointment "Completed", Rahul's ticket status updates instantly.
There are NO duplicate records, synchronizing scripts, or fragmented silos.

3. THE FREE-FIRST ARCHITECTURE PHILOSOPHY
====================================================================================================
The system is intentionally engineered to operate at approximately ₹0 per month during early and 
single-salon operations:
- Firebase Free Spark / Pay-as-you-go Blaze Tier (Firestore, Auth, and Storage stay well within free quotas).
- Vercel Free Tier (Hosting Next.js Server Actions and Route Handlers).
- Brevo Free Tier (Transactional Email delivery up to 300 free emails per day).
- Client-Side & Serverless PDF Generation (Using `jspdf` and `qrcode` without costly third-party PDF APIs).
- Hardware-Free Barcode / Ticket Scanning (Using WebRTC camera feed via `html5-qrcode` in browser—no 
  dedicated barcode hardware scanner required).
- Fallback-First Design: If an external service is unavailable (e.g., Brevo API quota exceeded), the 
  core booking flow never crashes; it logs the condition gracefully and fulfills the client request.

FIRESTORE SECURITY RULES (`firestore.rules`):
----------------------------------------------------------------------------------------------------
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function isAuthenticated() { return request.auth != null; }
    function isOwner() { return isAuthenticated() && request.auth.token.role == 'owner'; }
    function isStaff() { return isAuthenticated() && request.auth.token.role == 'staff'; }
    function isCustomer(userId) { return isAuthenticated() && request.auth.uid == userId; }

    match /services/{serviceId} {
      allow read: if true;
      allow write: if isOwner();
    }
    
    match /customers/{customerId} {
      allow read: if (isAuthenticated() && request.auth.uid == customerId) || isOwner() || isStaff();
      allow write: if (isAuthenticated() && request.auth.uid == customerId) || isOwner();
    }
    
    match /staff/{staffId} {
      allow read: if resource.data.isActive == true || isOwner() || isStaff();
      allow write: if isOwner();
    }
    
    match /appointments/{appointmentId} {
      allow create: if isOwner() || isStaff() || isCustomer(request.resource.data.customerId) || !isAuthenticated();
      allow read: if isOwner() || isStaff() || (isAuthenticated() && resource.data.customerId == request.auth.uid);
      allow update: if isOwner() || isStaff() || (isAuthenticated() && resource.data.customerId == request.auth.uid && request.resource.data.status == 'Cancelled');
      allow delete: if isOwner();
    }
    
    match /attendance_shifts/{shiftId} {
      allow read, write: if isOwner() || isStaff();
    }

    match /offers/{offerId} {
      allow read: if true;
      allow write: if isOwner();
    }

    match /{document=**} {
      allow read, write: if false;
    }
  }
}

6. AUTHENTICATION, ROLES & SECURITY ENGINE
====================================================================================================
Role Hierarchy:
1. `owner`: Has absolute management control over all salon operations, finances, catalog, staff.
   - Strictly SINGLE OWNER rule. System checks `adminAuth.listUsers` before assigning owner claim.
2. `staff`: Operates daily appointments queue, attendance shift punch clock, status progression.
   - Staff cannot self-register. Appointed by Owner or via Developer provisioning.
3. `customer`: Regular public user. Can be Guest (unauthenticated) or Registered.
   - Registered customers receive an 8-character unique ID, saved booking history, profile details.
4. `developer`: System maintenance role. Access to `/developer` for claiming roles.
   - Special privilege: appointments created by developer users are given high-visibility 
     gold-amber highlighting in the CRM table.

Role Provisioning Engine (`/api/dev/set-role`):
- Protected by a secret developer passphrase (`DEV_SECRET_KEY`).
- Validates that developer role can only be assigned to the designated master developer email.
- Enforces single-owner constraint: returns error if another owner already exists.
- Sets custom claims via `adminAuth.setCustomUserClaims(user.uid, { role })`.
- Auto-provisions a corresponding document in the `staff` collection if `role === 'staff'`.

Client-Side Role Protection:
- `RoleGuard`: Reusable wrapper component that checks user role against required permission list 
  and redirects unauthorized users.
- Role-based redirect on login:
  - Owner -> `/owner`
  - Staff -> `/staff`
  - Customer -> `/customer`

7. END-TO-END BUSINESS LOGIC & CRITICAL FLOWS

----------------------------------------------------------------------------------------------------
7.1 DYNAMIC RESERVATION & STAFF CONFLICT-RESOLUTION ALGORITHM (`createBooking` Action)
----------------------------------------------------------------------------------------------------
Workflow:
1. Validates that the requested service exists and has `isActive: true`.
2. Customer Identity Resolution:
   - If user is logged in (`userId`), links appointment to customer's account.
   - If guest, queries `customers` collection by email. If an existing record matches, reuses it.
     Otherwise, creates a new guest record with `isGuest: true`.
3. Candidate Staff Selection:
   - Queries `staff` where `isActive == true` and `services array-contains serviceId`.
   - If no staff member is specifically designated for this service, falls back to any active staff.
4. Slot Conflict Check:
   - Converts requested start time "HH:MM" into minutes from midnight: `reqStart = hours * 60 + mins`.
   - Computes `reqEnd = reqStart + service.durationMinutes`.
   - Fetches all existing appointments on the target date where status in `['Booked', 'Confirmed', 'In Progress']`.
   - Iterates through candidate staff members: checks if any of their booked appointments overlap:
     `Overlap condition: (reqStart < existingEnd) && (reqEnd > existingStart)`.
   - Assigns the first conflict-free staff member. If all candidate staff members are occupied,
     gracefully halts and informs the user that the slot is fully booked.
5. Record Creation:
   - Writes the appointment to Firestore with locked `priceAtBooking`.
6. Email & Ticket Dispatch:
   - Calls `sendBookingConfirmationEmail` with generated base64 PDF ticket.

7.2 BREVO TRANSACTIONAL EMAIL ENGINE & BASE64 PDF TICKET GENERATION (`brevoEmailService.ts`)
----------------------------------------------------------------------------------------------------
Ticket Design (Generated using `jspdf`):
- Dimensions: Standard A4 canvas.
- Header: Dark Charcoal banner (`#2B2B2B`) with centered white typography "Glow & Glamour Hair Studio".
- Title Banner: Light grey card with "OFFICIAL BOOKING TICKET".
- Left Column: Service name (22pt bold), Date, Time formatted in 12-hour AM/PM, Salon Address.
- Right Column: High-density scannable QR Code containing the Appointment ID, caption "SCAN TO VERIFY".
- Mid-Section: Hairline rule, Guest Name, Locked Amount in ₹, Assigned Staff member.
- Lower Badges: Alice Blue badge with shortened 12-char Booking ID, Light Green badge with Status.
- Footer: "Present this digital ticket at the front desk upon arrival."

Brevo REST Integration:
- Uses standard fetch to `https://api.brevo.com/v3/smtp/email` with header `api-key: process.env.BREVO_API_KEY`.
- Payload includes sender, recipient, rich HTML email layout, and `attachment` array containing 
  the base64 PDF string titled `Booking-[APPOINTMENT_ID].pdf`.
- Fail-Safe Guarantee: Entire email dispatch is wrapped in try/catch. A mail failure never aborts 
  or rolls back a confirmed booking.

----------------------------------------------------------------------------------------------------
7.3 REAL-TIME CAMERA QR CODE TICKET VERIFICATION (`/owner/scanner`)
----------------------------------------------------------------------------------------------------
- Uses `html5-qrcode` to bind directly to the device's camera (smartphone or laptop webcam) 
  inside an interactive frame (250x250 scanning window).
- Features manual Booking ID text fallback if camera permissions are blocked.
- On QR decode:
  1. Captures the decoded string (Appointment ID).
  2. Queries Firestore `appointments` by ID.
  3. Hydrates the appointment with Customer Name and Service Name.
  4. Displays a verification card with booking summary, price, and current status.
  5. Provides a 1-click button: "Mark as Completed", which updates status to "Completed" 
     and notifies via toast.

----------------------------------------------------------------------------------------------------
7.4 IST NIGHTLY AUTO-CANCELLATION & NO-SHOW CRON ENGINE (`/api/cron/auto-cancel`)
----------------------------------------------------------------------------------------------------
- Scheduled API endpoint triggered nightly via cron scheduler (Vercel Cron / GitHub Action / Cloud Scheduler).
- Timezone Awareness: Calculates India Standard Time (`Asia/Kolkata`) current date and hour.
- Cancellation Criteria:
  - Any active appointment ("Booked", "Confirmed", "In Progress") where `date < todayStr` (past date).
  - Any appointment where `date === todayStr` and `currentHourIST >= 20` (salon closing time: 8:00 PM).
- Actions:
  - Updates appointment status to "No Show".
  - Sends a polite auto-cancellation email to the customer via Brevo, explaining that the salon has 
    closed for the day and inviting them to rebook.

----------------------------------------------------------------------------------------------------
7.5 STAFF SHIFT CLOCK-IN / CLOCK-OUT ATTENDANCE SYSTEM (`/staff` + Server Actions)
----------------------------------------------------------------------------------------------------
- Every staff member has an operational dashboard at `/staff`.
- Daily Attendance:
  - "Clock In" action creates a record in `attendance_shifts` for `todayStr` with `status: 'Active'` 
    and server timestamp. Prevents duplicate clock-ins.
  - "Clock Out" action stamps `clockOutTime`, marks status as `'Completed'`, and updates record.
- Daily Roster:
  - Fetches today's appointments specifically assigned to the logged-in staff member.
  - Displays customer name, service name, time, and quick status action triggers (e.g. "In Progress", "Completed").

----------------------------------------------------------------------------------------------------
7.6 OWNER BILLING & CLIENT PDF INVOICING (`/owner/billing`)
----------------------------------------------------------------------------------------------------
- Lists completed appointments.
- Provides two invoice actions:
  1. "Download Invoice" (Saves PDF to user machine).
  2. "Print Invoice" (Opens print dialog in new window).
- Invoice Generation Engine:
  - Uses `jspdf` + `jspdf-autotable`.
  - Professional invoice header: Salon Name, Address, Contact, Official Invoice Number (`INV-[SHORT_ID]`).
  - Bill-To block with Customer Name, Email, Phone.
  - Formatted striped table with Service Description, Time Slot, and Total Amount in ₹.
  - Official sign-off footer: "Thank you for your business!".
